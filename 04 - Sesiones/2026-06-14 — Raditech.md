# Sesión 2026-06-14 — Raditech

Proyectos: [[Raditech]]

## Qué se hizo
- Diagnostiqué el snippet WPCode "Fix teleradiologia redirect" (ID 931): era PHP mal tipado como **HTML**, activo en *Site Wide Header*, por lo que imprimía el código como texto en la cabecera de todo el sitio. Lo desactivé y lo mandé a la papelera.
- Verifiqué que `/teleradiologia/` ya redirige bien a `/servicio-teleradiologia/` (301→200) y lo mantuve.
- Detecté que **7 de 8 redirects** `_wp_old_slug` devolvían **404** (la nota previa "Score 100%" era falsa).
- Causa raíz: `_wp_old_slug` es meta **protegido**; la REST API ignoraba en silencio los writes vía JWT.
- Creé el snippet WPCode **PHP** "Redirects 301 old-slugs Raditech" (ID 932): `template_redirect` + mapa old-slug→URL + `wp_safe_redirect(..., 301)`. **8/8 funcionando.**
- Purgué LiteSpeed "Vaciar todo" para limpiar el 404 privado cacheado del admin.
- Verifiqué 8/8 por código (anónimo y logueado) + screenshot visual.

## Decisiones técnicas
- Mapa PHP en `template_redirect` en lugar de `_wp_old_slug` (meta protegido, REST falla) o Rank Math Redirections.
- Mantener el redirect `/teleradiologia/` (un 301 de URL vieja a la nueva es bueno para SEO).
- Snippet único como fuente de verdad: para agregar redirects, editar el `$map` del snippet 932.

## Problemas encontrados
- `_wp_old_slug` vía REST falla en silencio (es meta protegido; requiere register_meta + auth_callback).
- WPCode: el **primer guardado no ejecutó** el snippet; hubo que **guardar una segunda vez (Update)** para que reconstruyera su caché interna y empezara a correr.
- LiteSpeed **caché privada por-usuario** mostraba el 404 viejo al admin logueado, aunque visitantes/Google ya recibían el redirect (`x-litespeed-cache: hit,private`). Se resolvió con "Vaciar todo".
